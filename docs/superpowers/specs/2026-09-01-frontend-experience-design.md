# V0 纯前端初步可视化验收版设计规格

日期：2026-09-01
状态：已实施并由用户确认验收通过；当前质量门禁和浏览器验收完成，纳入 V0 Git checkpoint
风险等级：L2（多页面视觉与基础交互 Feature/Batch）

## 1. 阶段目标

本阶段只解决一个问题：让用户第一次能够在手机浏览器中完整看见、点击和体验“六级词汇”的主要页面与核心路径，从而验收 UI、设计风格、页面结构、信息架构和基础交互。

本规格的实现原则是：**页面和交互看起来像真的，但内部业务逻辑可以暂时是 Mock。** 页面完整和视觉验收优先于状态、算法、数据和测试架构。

本阶段完成后，用户应能判断：

- 今日、学习、完成、进度、设置页面是否形成统一产品；
- TabBar、NavBar、卡片、按钮和拇指区操作的位置是否合理；
- 翻卡与选择题页面是否清楚、舒服；
- 完成与进度页面的信息是否容易理解；
- 设置页面的分组与控件是否合理；
- 320、375、430、600px 下是否正常；
- 产品结构或视觉方向是否需要在进入 V1 前调整。

本阶段是 `V0 / L2 / 初步可视化验收`，不是正式 MVP、完整交互 Prototype、正式状态管理、正式学习逻辑、FSRS 或持久化版本。

## 2. 成功路径

页面之间必须真实可跳转，并支持以下视觉 Demo：

```text
今日
→ 选择学习模式
→ 开始学习
→ 翻卡 / 选择题 Demo
→ 本组完成
→ 查看进度
→ 进入设置
```

每个箭头只要求真实页面跳转或当前页面内的可见反馈，不代表已经建立正式业务流程。允许使用固定 Mock 数据、页面局部状态、Router query 和确定性的演示结果。完成页与进度页直接展示固定结果：本组 6 词、认识 4、模糊 1、不熟 1，并明确标记“当前为 Mock 体验数据”。不得为了生成这些数字建设正式统计体系。

## 3. 页面与导航

### 3.1 必须完成的页面

| 路由 | 标题 | V0 职责 |
|---|---|---|
| `/` | 今日 | 今日任务、模式切换、开始学习、队列和最近结果 |
| `/study` | 学习 | 不依赖真实 Session 的翻卡或选择题可点击 Demo |
| `/study/complete` | 本组完成 | 固定 Mock 结果和三个后续入口 |
| `/progress` | 进度 | 固定体验数据的信息架构与视觉层级 |
| `/settings` | 设置 | 设置控件视觉、Disabled 能力和状态预览 |
| `/:all(.*)` | 页面不存在 | 404 兜底和返回首页 |

`/tokens` 保留为开发设计验收页，但从正式产品导航中移除。

### 3.2 正式一级导航

底部 TabBar 固定为：

```text
今日 | 进度 | 设置
```

- 今日、进度、设置显示 TabBar，不显示返回箭头。
- 学习、本组完成显示返回导航，不显示 TabBar。
- 404 显示“页面不存在”和一个明确的返回首页入口。

V0 不实现学习中返回恢复、继续学习、跨路由状态保持、Session 生命周期或路由守卫状态机。

## 4. 今日页

今日页必须展示真实视觉内容：

1. `CET-6 / V0 体验版` Eyebrow；
2. 页面标题与今日任务说明；
3. 本组词数和已完成数量；
4. 翻卡自评 / 选择题辨义切换；
5. 开始学习主按钮；
6. QueueBar；
7. 最近结果区域；
8. Mock 数据说明。

模式切换使用页面局部状态，并产生可观察的标题、说明或按钮文案变化。点击开始学习时使用 Router query 进入对应 Demo，例如 `/study?mode=flashcard` 或 `/study?mode=multiple-choice`。

V0 不创建正式 Session，不实现继续学习、恢复、跨路由结果累计或真实今日统计。

## 5. 学习页

学习页根据 Router query 选择翻卡或选择题 Demo。query 缺失或非法时回退到翻卡 Demo，不引入正式路由状态协议。

### 5.1 翻卡 Demo

使用固定 Mock 单词，完整展示：

```text
QueueBar
→ 单词
→ 音标
→ 查看释义
→ 中文释义、词性、例句
→ 认识 / 模糊 / 不熟
→ 下一词 / 完成
```

交互要求：

- “查看释义”通过页面局部 `ref` 展开内容；
- 点击三档评分后显示基础选中反馈和“下一词”按钮；
- 点击下一词只调整当前页面的演示索引，并重置本页展开/选中状态；
- 第 6 个词后按钮显示“查看本组结果”，点击进入 `/study/complete?mode=flashcard`；
- 发音按钮 Disabled，并说明“V0 暂未接入，后续阶段实现”。

演示索引只用于让用户看到不同词卡和最终跳转，不生成、累计或传递正式学习结果。V0 不把三档操作写入正式 `good/hard/again` 业务语义，不计算下次复习时间，不持久化，也不建设防重复计分体系。

### 5.2 选择题 Demo

使用 6 道固定 Mock 题，每题数据直接包含单词、音标、四个中文选项和正确选项索引。

完整展示：

```text
QueueBar
→ 单词 + 音标
→ 四个中文释义
→ 用户选择
→ 正确 / 错误反馈
→ 下一题 / 完成
```

交互要求：

- 四个选项视觉完整，点击后锁定当前题的选择；
- 反馈同时使用文字、图标和颜色，不只依赖颜色；
- 点击“下一题”只调整当前页面的演示索引；
- 第 6 题后进入 `/study/complete?mode=multiple-choice`。

演示索引和当前选项只用于视觉反馈，不生成完成结果。V0 不实现干扰项算法、答案位置算法、选择题计分体系、结果累计、独立纯函数或相关业务测试。

## 6. 本组完成页

完成页不依赖真实 Session，可直接访问，并重点验收学习结束后的视觉反馈。页面固定展示：

- 本组完成；
- 完成 6 词；
- 认识 4、模糊 1、不熟 1；
- 选择题模式额外显示固定正确数量；
- QueueBar；
- “当前为 Mock 体验数据”的说明。

三个入口必须真实可点击：

- “返回今日”跳转 `/`；
- “查看进度”跳转 `/progress`；
- “再来一组”根据当前 query 重新进入 `/study`。

“再来一组”只是重新打开对应 Demo 页面。V0 不创建完成结果对象，不实现 Session 清理、重开、Reset 完整语义或统计写入。

## 7. 进度页

进度页不读取学习页产生的任何状态，直接使用固定 Mock 数据验收未来信息架构，展示：

- 已体验词数；
- 目标词量；
- 认识、模糊、不熟；
- 最近一次学习结果；
- QueueBar；
- “当前为体验数据，不代表真实学习历史”的说明。

V0 不实现长期历史、正式统计模型、图表库、趋势、连续学习天数或持久化。

## 8. 设置页

设置页重点验收分组、控件、文案和 Disabled 状态：

### 学习偏好

- 默认模式：页面局部模式切换；
- 目标词量：页面局部 Slider，默认 2500，范围 1000～5000，步长 500；
- 控件变化只更新设置页当前实例的说明文字；离开页面后无需保持，也不写入全局 Store 或浏览器存储。

### 体验功能

- 自动发音：Disabled，说明后续接入 TTS；
- 备份恢复：Disabled，说明后续接入正式本地数据协议；
- 重置体验：可以打开确认 Dialog，并只恢复设置页局部控件；它不承担清理学习、完成、进度或任何全局状态的语义。

### 状态样式预览

使用页面局部切换展示 Loading、Empty、Error 和 Disabled 的 UI 样式。它只用于视觉验收，不影响今日或进度页，也不创建全局 Experience Store。

## 9. Loading、Empty、Error、Disabled

这些状态属于 V0 的 UI 验收范围，不属于正式状态系统。

- `StatePanel` 提供 Empty、Error 和 Disabled 的一致视觉外壳；
- Loading 使用 Vant Skeleton 或等价的现有组件；
- 设置页提供局部状态预览入口；
- Error 示例包含一个可点击“重试”按钮，并仅切回局部默认预览；
- Disabled 示例明确说明不可用原因和后续阶段；
- 不在多个产品页面接入全局场景切换。

## 10. Mock 数据与状态原则

### 10.1 Mock 数据

- 使用 6～12 个固定 Mock 单词；学习 Demo 每组展示 6 个；
- 覆盖单词、音标、释义、词性、例句和固定选择题选项；
- 数据放在 `src/constants/mock-words.ts`，与未来正式词库明确隔离；
- 页面显著标注 Mock，不接入 5651 词正式词库、数据库、API 或同步。

### 10.2 状态优先级

V0 依次使用：

```text
页面局部 ref / reactive
→ 固定 Mock 数据
→ Router query
```

Router query 只用于告诉页面展示哪一种 Demo，不构成正式状态协议。V0 不为页面 Demo 新建 Store、Service、业务 composable 或跨页面共享状态。

不创建完整 Experience Pinia Store，也不实现：

- `createSession`；
- `continueSession`；
- `submitRating`；
- `submitAnswer`；
- `finishSession`；
- `restartSession`；
- `resetSession`；
- 结果累计；
- Session 生命周期；
- 跨路由恢复。

## 11. 组件边界

只创建已经确认具有视觉复用价值的组件：

### `src/components/ui/`

- `Eyebrow.vue`；
- `StatCard.vue`；
- `StatNumber.vue`；
- `SegmentToggle.vue`；
- `StatePanel.vue`。

### `src/components/word/`

- `QueueBar.vue`；
- `RateButtons.vue`。

词卡和选择题选项在 V0 中保留在学习页，不为未来可能复用继续拆分。组件 props 不超过 6 个，组件内部只写 `padding` 不写 `margin`。

执行优先级固定为：

```text
页面完整度 > 视觉一致性 > 使用体验 > 组件抽象程度
```

## 12. 设计约束

- 使用现有青墨品牌色、纸质浅底、衬线单词、横线段 QueueBar 和三档评分色；
- 视觉模式为移动端工具的 `Operate` 模式；
- 不增加第二套 UI 库或图标库；
- 不增加渐变、深色模式、插画、复杂图表或新的设计语言；
- Vant 外观只通过主题变量配置，不写 `.van-*` 样式覆盖；
- 新视觉值优先复用现有 Token；只有现有 Token 无法表达必要样式时，才在 `src/styles/tokens.less` 增加最小 Token；
- 页面和组件不写字面颜色、字号、圆角和间距；
- 不修改已定稿的 `设计系统.md`。

## 13. 响应式与无障碍

集中检查 320、375、430、600px：

- 页面是否横向溢出或过度拥挤；
- 单词、中文释义和例句是否破坏布局；
- 字号、卡片密度和按钮尺寸是否合适；
- 底部操作是否被安全区、TabBar 或浏览器 UI 遮挡；
- 学习页是否适合单手操作；
- 600px 最大显示宽度下是否仍保持移动端产品比例。

交互状态不能只依赖颜色；按钮、选项、Slider 和切换需要可理解标签；保留全局键盘焦点；遵循 `prefers-reduced-motion`，减少动效时取消非必要动画。

## 16. 验证策略

### 自动化质量门禁

运行：

```text
pnpm typecheck
pnpm lint
pnpm build:pro
```

项目已有 `pnpm test` 可以作为低成本回归额外运行，但不是 V0 新页面的专项业务验收门槛。V0 不新增 Store 测试、选择题算法测试、结果统计纯函数测试、业务单元测试框架或大量业务测试。

继续运行工程规范扫描：Vant 变量、`.van-*`、字面颜色、`src/api/`、组件 `margin` 和重复结构人工检查。

### 浏览器集中验收

一次集中检查：

```text
今日 → 翻卡 Demo → 完成
今日 → 选择题 Demo → 完成
完成 → 进度
TabBar → 今日 → 进度 → 设置
404
Disabled 状态
Loading / Empty / Error UI 示例
```

以上流程在 320、375、430、600px 下检查。发现阻断性视觉和交互问题后集中修复一次，再做一次确认检查并停止，不进行无限视觉打磨。

### L2 Checkpoint

V0 不执行 L3 重型独立 Review。以一次 Feature/Batch Checkpoint 完成 diff、规范和集中浏览器检查；只有出现阻断性问题时进行一次集中修复，不为视觉微调追加多轮 Review。

## 17. 完成定义

只有同时满足以下条件才完成 V0：

1. 用户第一次可以完整看到整个产品主要页面；
2. 所有主要页面有真实视觉内容，不是空壳；
3. 翻卡和选择题都能完成简单可点击 Demo；
4. 核心页面之间能够真实跳转；
5. 视觉风格统一并遵守现有设计系统；
6. 320、375、430、600px 没有阻断性布局问题；
7. 所有主要按钮有基础可观察反馈；
8. 未实现功能明确 Disabled 并说明原因；
9. Mock 数据有明确标记；
10. typecheck、lint 和生产构建通过；
11. 浏览器控制台没有阻断性错误；
12. 完成一次集中视觉验收后停止开发。

交付时必须列出：

- 实际修改的页面；
- 实际修改的组件；
- 使用的 Mock 行为；
- 故意没有实现的行为；
- 自动化检查结果；
- 四种视口检查结果；
- 仍存在的视觉风险。

完成后停止，让用户亲自运行和验收。只有用户明确确认 V0 产品结构和视觉方向后，才重新规划 V1 的 Pinia、Session、评分、结果统计、状态系统和测试。
